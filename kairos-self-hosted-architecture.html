Kairos self-hosted architecture

Kairos を自前環境で動かすための最小構成

Linear の issue やコメントを起点に、EdgeWorker がイベントを受け、Codex runner が隔離された作業環境で実装・検証・PR作成までを実行する構成です。 egress proxy と sandbox を分離することで、ネットワークとファイルシステムの境界を運用側で制御できます。

リクエストからPRまで

Linear

Webhook が作業依頼を通知

issue 作成、コメント、ステータス変更を署名付き webhook として送信します。

EdgeWorker

認証とキュー投入

署名検証、重複排除、ジョブ正規化を行い、runner に渡す実行単位へ変換します。

Codex runner

作業用 worktree で実行

リポジトリを取得し、Codex がコード変更、テスト、commit、push を行います。

GitHub PR

レビュー可能な成果物へ

作業ブランチから Pull Request を作成し、Linear issue へ結果を戻します。

EdgeWorker

外部公開される唯一の入口です。Linear webhook の署名検証、イベントの idempotency、runner へのジョブ配送を担当します。

Codex runner

ジョブごとに worktree を分離し、必要なツールを呼び出します。成果物は commit と PR に集約されます。

Sandbox

ビルド、テスト、任意コマンドの実行境界です。ファイルアクセス、プロセス、環境変数を runner のポリシーで制限します。

Egress proxy

外向き通信を集約し、許可ドメイン、監査ログ、レート制限、認証情報の注入ポイントを一箇所にまとめます。

Secrets

Linear、GitHub、LLM provider の token は runner コンテナへ直接焼き込まず、実行時に必要最小限だけ渡します。

Observability

job id、Linear issue、branch、PR番号を紐づけ、ログとメトリクスから実行履歴を追跡できるようにします。

docker-compose の考え方

本番相当のセルフホストでは、公開入口、実行基盤、外向き通信、永続化を別サービスとして切ります。 これにより、runner を水平スケールしながら webhook 受付や監査の責務を小さく保てます。

  • edgeworker: webhook 受付、署名検証、ジョブ作成
  • runner: Codex 実行、git 操作、PR作成
  • egress-proxy: 外向きHTTPの制御と監査
  • postgres / redis: ジョブ状態、ロック、再試行管理
services:
  edgeworker:
    image: kairos/edgeworker
    ports:
      - "8080:8080"
    environment:
      LINEAR_WEBHOOK_SECRET: ${LINEAR_WEBHOOK_SECRET}
      JOB_QUEUE_URL: redis://redis:6379

  runner:
    image: kairos/codex-runner
    environment:
      GITHUB_TOKEN: ${GITHUB_TOKEN}
      CODEX_EGRESS_PROXY: http://egress-proxy:3128
      SANDBOX_ENDPOINT: http://sandbox:9090
    volumes:
      - runner-worktrees:/worktrees

  sandbox:
    image: kairos/sandbox
    read_only: true

  egress-proxy:
    image: kairos/egress-proxy
    ports:
      - "3128:3128"

  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: kairos

  redis:
    image: redis:7

volumes:
  runner-worktrees:

セキュリティ境界

webhook 受付とコード実行を同じ信頼境界に置かないことが、セルフホスト運用で最も重要な設計判断です。
  • Linear からの入力は EdgeWorker で検証し、runner には正規化済みジョブだけを渡します。
  • runner の外向き通信は egress proxy 経由にし、許可先と監査ログを集中管理します。
  • sandbox はジョブ単位で破棄できる前提にし、worktree、依存キャッシュ、秘密情報を分離します。
  • PR 作成後は Linear に結果を返し、実装ログ、テスト結果、レビュー対象のリンクを追える状態にします。

このページはセルフホスト構成を説明するための簡略図です。実運用では認証、監査、キューの再試行、runner の並列数、secret rotation を環境に合わせて調整します。
